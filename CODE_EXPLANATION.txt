# MBPP Experiment Codebase Explanation

## Overview
This codebase implements a multi-phase experiment system for testing language models (like GPT-4) on programming problems from the MBPP dataset. The system is designed to:
1. Generate solutions to programming problems
2. Test these solutions
3. Refine solutions based on test results
4. Track and analyze performance across different phases

## Core Components

### 1. run_experiment.py (Main Runner)
The central orchestrator that:
- Manages experiment runs
- Handles command-line arguments
- Creates directory structures
- Coordinates between phases
- Tracks progress
- Handles interruptions and resumption

Key Functions:
- `create_timestamped_dir()`: Creates unique directories for each run
- `find_latest_run()`: Locates most recent experiment for resumption
- `run_experiment()`: Main function coordinating all phases
- `update_progress()`: Saves progress after each problem
- `create_run_summary()`: Combines results from all phases

### 2. mbpp_experiment.py (Phase 1)
Implements the basic problem-solving phase:
- Reads problem statements
- Generates initial solutions
- Tests solutions against basic test cases
- Records results and statistics

Key Features:
- Direct solution generation from problem statement
- Basic test case validation    
- Performance metrics collection

### 3. mbpp_experiment_phase2.py
Enhances solution generation by:
- Analyzing test cases before generating solutions
- Using test cases as additional context
- Implementing more sophisticated testing
- Tracking success rates with test-informed solutions

Key Improvements:
- Test case analysis
- Context-aware solution generation
- Enhanced validation

### 4. mbpp_experiment_phase3.py
Implements iterative refinement:
- Takes failed solutions from previous phases
- Analyzes failure patterns
- Attempts multiple solution refinements
- Tracks improvement across iterations

Special Features:
- Failure analysis
- Multiple solution attempts
- Progressive improvement tracking

## Data Flow

1. Problem Selection:
   - Problems loaded from MBPP dataset
   - Filtered based on start_id and num_problems
   - Distributed to each phase as needed

2. Solution Generation:
   Phase 1: problem_statement → solution
   Phase 2: (problem_statement + test_cases) → solution
   Phase 3: (failed_solution + error_analysis) → refined_solution

3. Result Storage:
   - Solutions saved in phase-specific directories
   - Statistics collected for each phase
   - Progress tracked in progress.json
   - Final summary in run_summary.json

## Common Workflows

1. New Experiment:
   ```bash
   python run_experiment.py --problems 50 --start 200 --model gpt-4o
   ```

2. Resume Interrupted:
   ```bash
   python run_experiment.py --resume
   ```

3. Single Phase Test:
   ```bash
   python run_experiment.py --phases 1 --problems 5
   ```
